# 采集工作台 · 任务与物料

以物料为中心管理机器人数据采集任务。所有人可浏览和导出，只有被授权的 ChatGPT 账号可编辑。

## 两张表

- **任务表**：每行一个任务，记录任务名称、所属场景、涉及物料、任务说明（状态保留在详情中维护）。一个任务可以关联多种物料与多个场景，不指定物料的具体款式。
- **物料表**：每行一种物料，款式图片横向排列，不设置所属场景。款式列随实际图片数量增加，每种物料最多支持 100 个款式；物料名称下方有“添加款式”入口。点击图片看原图；点击物料名称编辑名称、备注、款式图片。

支持搜索、场景和状态筛选、分页、批量新增名称、CSV 导出、记录归档和恢复。被任务使用的物料不能直接归档。编辑保存使用版本检查，拒绝覆盖别人已经更新的记录。

## 初始数据

`data/seed.json` 包含经用户授权公开的 305 条京东任务和 135 个从场景样例提取的物料名称。任务保留中文翻译、英文原文和原表行号，初始状态为待整理，未自动分配场景或物料。类别沿用原场景样例。原表中的环境照片不是单件物料款式图，因此没有当作款式图片导入。

这只是首次初始化数据。网页里后续保存的数据在云端数据库中，图片在云端对象存储中，不会自动写回此仓库或桌面 Excel。重新部署不会覆盖已保存的记录。

## 在线使用

1. 打开网页，点击“登录编辑”，使用已授权的 ChatGPT 账号登录。
2. 物料表中点击名称，添加款式照片并保存。每张支持 JPG、PNG、WebP，最大 10MB；自动生成预览缩略图。
3. 任务表中点击任务，选择场景和物料，再填写采集要求。填写场景和物料后可以推进任务状态。
4. 以后需要更多款式，继续向该物料添加图片；需要更多任务，可批量粘贴任务名称。

初版为单人使用并预留成员授权。新增编辑者需配置服务器的 `EDITOR_EMAILS`，使用逗号分隔邮箱；不应把编辑权限名单或凭据提交到公开仓库。GitHub 协作者权限与网页数据编辑权限分别管理。

## 运行与部署

Node.js 22.13+。使用项目现有的安装与构建脚本。

```sh
npm ci
npm run db:generate  # 仅修改数据库结构后使用；已有迁移不要重新生成
npm run dev -- --hostname 127.0.0.1 --port 5173
npm run build
```

本项目使用 React / Vinext，部署到 Sites / Cloudflare Workers。数据库使用 D1，图片使用 R2。GitHub 保存源码和初始数据；GitHub Pages 单独无法运行这里的登录授权、数据库写入和图片上传。

- `.openai/hosting.json` 声明站点和存储绑定；部署时使用 Sites 发布流程。
- `db/schema.ts` 是表结构，`drizzle/` 保存不可变迁移。部署会应用尚未执行的迁移。
- `OWNER_EMAIL` 是初始编辑者账号；`EDITOR_EMAILS` 是其他编辑者邮箱列表。通过 Sites 的环境变量配置功能设置，不能放到前端代码。
- 生产环境的身份由 Sites 登录入口提供，服务器检查编辑名单并绑定稳定的站点用户 ID。任何写操作还需通过来源与数据校验。
- 本地预览有独立数据库、文件存储和模拟登录。复制 `.dev.vars.example` 为 `.dev.vars` 后填入预览配置；本地模拟账号仅供开发，不用于生产。
- 图片随数据公开可访问。移除款式会解除图片关联，当前不会永久删除存储中的原图。

当前适合首批数百条任务的管理：列表按页加载，款式图懒加载。尚未进行大规模压力测试；若增长到数万条记录，应进一步优化关联查询、导出与批量操作。

本地浏览器验证了登录编辑、物料保存和图片上传；接口检查覆盖匿名拒写、来源检查、任务关联、状态校验、编辑冲突、归档恢复、物料引用保护、CSV 导出和分页。
